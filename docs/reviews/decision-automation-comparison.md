## Limitations and non-blocking uncertainties

1. **Semantic model quality and task completeness.** Strict parsing, meaningful
   bounded strings and graph validation cannot prove an option is substantively
   correct, its regenerated ID denotes the same meaning, or a proposed changed
   guarantee has every necessary implementation/review task. The observation
   states document edits do not automatically synthesize follow-up tasks.
   Exact human review of the typed plan remains necessary; the tested full
   follow-up chain is positive evidence, not universal semantic proof. No
   observed accepted plan missing a demonstrably required task is supplied.
2. **Bounded snapshot coverage.** Freshness applies to the explicit local
   capture inventory and consumed aliases, not every repository file. Nested
   components are excluded from implementation recursion. There is no evidence
   of an unbound consumed input in this comparison; nevertheless a whole-
   repository freshness guarantee would exceed what was observed.
3. **Manual/review distinction.** Manual import without an exception still
   requests advisory review. “Requires no model” describes the available
   deliberate-exception path, not an unconditional promise to bypass required
   per-plan review. No-agent failures must not be treated as an implicit pass.
4. **Operational proof bounds.** Mock gateways establish protocol/context/
   ordering assertions, not real-model reliability or correct stakeholder
   judgment. Generated-text attention assertions are not executed command
   tests. Failure injection does not exhaust every crash/power-loss race.
   Secret creation/ownership helpers were outside the source observation's
   inspection, and proof of actual human preview inspection is not supplied.
5. **Platform and publication bounds.** Linux path defenses have scoped source/
   test evidence; equivalent race resistance on every platform is not
   established. The requirements currently limit executable support to Linux.
   No-model/no-Git claims apply to isolated apply, not the separately opted-in
   ordinary runner and its policy-controlled local checkpoints.
6. **Validation scope.** Completed passing tests and the final corrected
   observation support this diagnostic. They do not certify every maerg
   requirement, ignored tests, independent final review of arbitrary future
   work or native acceptance enforcement. Later lint, build and focused-test
   results are separately attributed above, not independently inspected here.
